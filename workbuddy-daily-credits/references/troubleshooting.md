# 故障模式详录（排查疑难时读）

本文件记录本 skill 开发过程中**实际踩过的坑**，每个都附带根因与判定方法。遇到脚本行为异常时按此对照。

---

## 1. 陈旧帧（renderer wedged）— 头号隐蔽故障

**症状**：卡片显示「今日已领」，但当日实际未领 → 假 `ALREADY_DONE` → **漏领**。

**迷惑点**：窗口**可见**、标题正常、消息循环正常（`WM_NULL` 有响应、`IsHungAppWindow=False`、可最小化还原），只有 renderer 挂了。

**判据**：
- 探针点击（如点侧栏「资料库」）后比对重绘像素差；**0 或极小 ⇒ wedged**
- 交叉铁证：今日帧与某历史帧**逐像素完全相同**（maxdiff=0）

**自愈**：杀主进程下的 `--type=renderer` 子进程 → Electron 自动重载页面。
- ⚠️ 先杀 `gpu-process` **无效**（窗口变黑但 renderer 仍不重绘）
- ⚠️ 重载后 **hwnd 会变**、窗口可能漂屏，必须重新 `find_window`
- ⚠️ 脚本须**排除自身祖先链**，绝不误杀承载 agent 会话的进程

**实测阈值**：正常存活时探针差约 6600–35000；wedged 时接近 0。
> 注意：阈值 3000 在「探针点到了不引起重绘的位置」时可能误判为 wedged。误判的代价只是多重启一次 renderer（无害），可接受。

## 2. 更新提示条 → OCR 假阳性 → 点错坐标

**症状**：卡片明明 S1，脚本连续多次点击全部落空，每次点击后仍 S1。

**根因**：客户端弹出「新版本就绪 / 更新日志 / 重启升级」更新条，固定贴侧栏最底部（并**盖住账户行**）。该区域 OCR 会吐出**假阳性「立即领取」**，且分数**可能高于卡通内真按钮** → `best_hit` 选中错误坐标。

**修复**：
- `sanitize_hits()`：剔除更新条锚点水平带（±28px）内的所有命中
- `card_band()` / `judge()`：只在卡片纵带内判定（同时防噪声**伪造 S2**）
- `dismiss_update_bar()`：点更新条右上角 ×（相对「重启升级」偏移 `(+55,-21)`）
- ⚠️ **绝对不要点「重启升级」**

## 3. ⛔ 误诊案例：曾以为「任务列表过长 → 卡片被挤出视口」

**这一条记录的是一个错误结论，保留是为了防止后人重复踩坑。**

**曾经的（错误）结论**：侧栏底部卡片是 layout 流内元素，任务列表太长时被挤到视口外，
滚动无效；判定为「取决于用户任务数、与屏幕无关、换机最易踩的坑」。

**这个结论是错的。** 实测证明：**账户行与任务列表是两个互不相干的控件**，
不存在挤压关系。抓了同时包含「Buddy加油站·10期」和「刘潇潇 Sean」的帧，
两者同时可见，中间夹着任务项 —— 卡片根本没被挤走。

**真正的根因**：探测脚本运行时，**上一轮遗留的账户菜单/面板还开着**，
抓到的根本不是主界面帧，所有推断都建立在脏帧上。

**真正的修复**：新增 `reset_ui_state()`，**先于一切读取**执行 —— 移开鼠标 + Esc，
并用「仅浮层才有」的标记判断浮层是否收干净。

> **教训**：不要在没有复位 UI 状态的情况下做「读画面 → 推断」。
> 这是本项目历史上多次误诊的共同根因。

**另外**：侧栏底部**本来就没有常驻的积分卡片**。积分入口是
「点击账户行 → 菜单 → Buddy加油站」，见下一条。

## 3b. 侧栏底部没有常驻积分卡片 / 积分入口的真实结构

**症状**：整屏 OCR 在侧栏底部找不到任何 `Buddy加油站` / `每日可领` / `立即领取` 锚点，
只有一串任务名和账户行。

**根因**：这是**正常现象**，不是故障。干净主界面的侧栏底部只有账户行 + 2 个图标
（通知 / 反馈）。积分卡片是**点击账户行后弹出的覆盖层**，不存在于主界面。

**正确做法**：走路径 1 —— 点账户行 → 账户菜单 →「Buddy加油站」→ 积分面板。

**账户菜单完整内容（实测）**：
```
套餐 / 积分余额 / [升级套餐]
Buddy加油站（每日领积分）      ← 积分入口，菜单较靠上
去邀约 / 成长计划
设置 / 外观 / 记忆与进化 / 意见反馈 / 检查更新 / 退出登录
```

## 4. 账户菜单 toggle 语义

**症状**：点了账户行，菜单却没出现（或本来开着反而被关掉）。

**根因**：账户菜单是 **toggle** —— 已展开时再点会收起。

**判定菜单是否展开**：只能用**菜单专属**标记
`积分余额` / `购买积分` / `去邀约` / `成长计划` / `记忆与进化` / `退出登录`。

**关键陷阱**：**不能用「Buddy加油站」判断** —— 它同时出现在（a）菜单项、（b）积分面板标题。
用它判断会把「面板已开」误认成「菜单已开」，于是跳过点击、直接去找菜单项，必然找不到。
> 实测踩坑：连续两次运行后残留面板未关，第二次运行误判「菜单已展开」→ `NO_GAS_PANEL`。

## 4b. 主对话区的同名文字把点击/读数带偏（新故障模式）

**症状**：面板明明开着，点击「立即领取」却总是无效（点击后仍 S1）；
或 T2 读到的数字**比实际少 1 天**（读到昨天的汇报文本）。

**根因**：面板打开时，主对话区可能正显示含「立即领取 / 今日已领 / 已领12天 / 累计领取1200分」
的**历史汇报文本**（自动化自己的输出、或用户聊积分的话题）。
这些文本的 OCR 分数（实测 **0.92**）**高于**面板真实读数（**0.70–0.86**）。
不限区域 → `best_hit` 选中对话区坐标（实测点到 `(2850,161)`、`(3400,477)` 的聊天消息上）；
`parse_t2` 也读到对话区里的**昨天数字**。

**修复**：`panel_region()` 用**面板专属锚点**（`Buddy加油站`+`期` / `每日可领通用积分` /
`累计领取`）反推面板矩形；`panel_state()` 与 `parse_t2()` 一律**只在区域内**取候选。

**判定**：日志里 `[panel] 面板区域 (...)` 行的矩形是否覆盖真实面板位置；
若 `立即领取` 的命中坐标在主对话区（x 很大、y 很小），就是这个故障。

## 5. DPI 缩放导致坐标系混用

**症状**：OCR 找不到入口、所有点击落空。`GetWindowRect` 返回**异常大的矩形**（如 2582x1422 → 3873x2133，正好 1.5 倍）。

**根因**：多屏不同缩放时（如主屏 1920x1080@150%、副屏 2560x1440@100%），若进程 DPI-unaware，`GetSystemMetrics` 报缩放后的逻辑尺寸，而 `GetWindowRect` / `mss` 用物理像素 → 坐标错位约 950px。

**修复**：进程启动**最早期**（早于 import pyautogui）调用
```python
ctypes.windll.shcore.SetProcessDpiAwareness(2)   # per-monitor v2
```

---

## 6. 窗口被隐藏（SW_HIDE）

**症状**：`find_window` 报 `NO_WINDOW`，但进程存在。

**根因**：窗口被外部脚本 `SW_HIDE` 隐藏（`IsWindowVisible=False` 但 hwnd 仍在）。若 `find_window` 只收集可见窗口 → 误报无窗口。

**修复**：`find_window` 同时收集隐藏主窗口（按可见优先排序）；`activate()` 对隐藏窗口先 `SW_SHOW`（`SW_RESTORE` 对 hidden 窗口**不够**）。

---

## 6b. 窗口被最小化 → rect 是 -32000 哨兵 → 整轮跑飞

**症状**：日志里 `窗口矩形: (-32000, -32000, ...)` / `抓取 237x39`，
之后所有路径都 S3、OCR 全部无命中，最后 UNKNOWN。

**根因**：最小化（iconic）窗口的 `GetWindowRect` 返回 **-32000 哨兵值**
（本机 DPI 缩放下是 -21333）。对这样的窗口截图只会得到 237x39 的**假帧**。
`win32gui.ShowWindow(hwnd, SW_RESTORE)` 对最小化窗口**无效**（实测 `IsIconic` 仍为 1）。

**修复**：`activate()` 中按序尝试并**逐步校验**：
1. `ShowWindowAsync(hwnd, SW_SHOWNORMAL)` ← **这个稳定生效**
2. `ShowWindowAsync(hwnd, SW_RESTORE)` ← 有竞态，时灵时不灵
3. `SetWindowPos(..., SWP_SHOWWINDOW)` ← 最后手段

还原后校验 rect 是否仍 ≤ -32000，是则告警。
`find_window()` 也把非最小化窗口排前面，并记录最小化候选数量。

---

## 7. 屏幕截图抓到别的窗口（历史误判根源）

**症状**：既会假成功也会假失败，结论飘忽。

**根因**：客户端置前经常失败（前台被 Edge / 微信占用），用屏幕区域截图抓到的是**别的窗口**的画面。

**修复**：一律用 `PrintWindow(PW_RENDERFULLCONTENT=2)` 抓窗口**自身**内容，免疫遮挡与前台状态。

---

## 8. 形近字 OCR 混淆

**实测**：「今日已领」被识别成「今日已**额**」→ S2 判定失败 → 脚本误判未成功并重复点击（幂等无害，但浪费轮次）。

**修复**：关键词匹配前做归一化 `_CONFUSABLE = {"额": "领"}`；匹配阈值从 0.6 降到 0.5（灰底胶囊上的小字识别分偏低）。

## 9. 硬编码用户名的陷阱（泛化必修）

**症状**：脚本在作者机器上正常，换台机器永远 `NO_ACCOUNT`。

**根因**：把用户名「刘潇潇 Sean」写死。

**修复（v7.5.1 后的正确做法）：纯几何定位，不猜姓名格式。**

> ⛔ **曾经的错误做法**（已废弃）：按「侧栏 x 带 ∩ 纵向底部 ∩ 含 CJK ∩ **以拉丁字母结尾**」
> 的结构化特征识别。**这个假设是错的** —— 用户可能用纯英文名、纯中文名、带数字、
> 带邮箱、带表情符号……任何格式都可能。识别一个 UI 元素，不该去猜它的**内容长什么样**。

**正确判据（三条，均为几何/结构事实）**：
1. 位于侧栏 x 带内（`rect[0]` ~ `rect[0] + sidebar_w(rect)`）；
2. **紧贴窗口底边**：距底边 `< 0.09H`
   （实测账户行 0.044H，其上方最近一条 0.101H，有 **2.3 倍**间隔，阈值取中很稳）；
3. 位于面板锚点**之下**（账户行是侧栏最低的条目）。

再排除卡片/面板自身的文字与用量、升级等噪声。**内容格式完全不影响判定。**

⚠️ **另一个坑**：若确要用文本判断，必须用**原始文本**。`norm_txt()` 会删除空格，
使「刘潇潇 Sean」粘连成「刘潇潇Sean」，按空格切分必然失败。
**但既然已改为几何定位，就不要再引入文本格式假设了。**

## 10. 误选同名文本（T2 复核）

**症状**：T2 读出 `(None, None)`，或读到比实际少 1 天的数字。

**根因**：主窗口停在「资料库」页时，内容区**所有者列**也存在用户名，且 OCR 分更高
（0.837 > 侧栏 0.816）→ `best_hit` 误选 → 点开文档而非账户菜单。
同理，主对话区的历史汇报文本含「已领12天/累计领取1200分」，分数（0.92）高于面板真实读数。

**修复**：一切候选先按**区域**过滤 —— 账户候选限定在侧栏 x 带 + 贴底带；
T2 与按钮候选限定在 `panel_region()` 内（见第 4b 条）。

**同类陷阱**：整屏 OCR 找「Buddy加油站」时会命中侧栏卡片标题「Buddy加油站·N期」
（纯文字不可点）→ 需排除含「期」「结束」的命中。

## 11. 快路径（claim_fastpath.json）相关

### 11a. 快路径失效 → 自动回退（**正常行为，不是故障**）

**症状**：日志出现

```
[fast] 失效标记：点账户行后菜单未弹出（坐标可能已失效）（fail_streak=1）
[路径0] 快路径不可用 → 本次回退完整流程（仍会正常完成）
```

**这不是故障，是设计如此。** 客户端改版、窗口尺寸变化、系统缩放变化都会让旧坐标失效，
脚本检测到后主动放弃缓存、回退完整流程，并在成功后**自动重新固化正确坐标**。
本轮仍会正常领到，只是慢一点（~47s vs ~13s）。

**要做的**：什么都不用做。看日志确认回退了、且最终拿到了结果即可。

### 11b. 何时该手动删缓存

```bash
rm <skill目录>/scripts/claim_fastpath.json
```

- 刚改过脚本的坐标/锚点常量 → 旧缓存已失效，删掉可少走一轮
- 升级客户端版本后 → 同上
- 怀疑缓存有问题、想强制重新探测

删掉后下次运行会走完整流程（~39s）并自动重建缓存。

### 11c. 缓存为什么可以放心存在（安全设计）

| 机制 | 说明 |
|---|---|
| 只省「定位」 | 判定仍走 `claim_on_panel()`，与完整流程**同一套** T1/T2 标准 |
| 点账户行后校验菜单 | 坐标点偏会落到别的菜单项上 → 必须拦（已验证） |
| 单次失败不删 | 防偶发（动画慢）误删好缓存 |
| 连续 2 次失败才删 | 真失效才放弃 |
| 成功后重固化 | fail_streak 自动清零，缓存自动跟上当前 UI |
| 缓存损坏/schema 不符 | 静默忽略，走完整流程 |

**实测闭环**：注入坏坐标 → 检出失效 → 回退完整流程成功 → 自动重新固化正确坐标 → 下次回到快路径。

## 通用排查顺序

1. **先看是不是最小化窗口**：日志里 `窗口矩形` 是否含 `-32000` / 抓取尺寸是否 237x39
   → 走第 6b 条
2. **看日志的逐路径记录**，确认走到了哪条路径、卡在哪一步
3. **看 `claim_pre.png` / `claim_result.png`**，目视确认画面到底是什么状态
4. 若 `claim_result.png` 是黑屏/空白 → 截图通道问题（PrintWindow 失败）
5. 若画面里找不到积分锚点 → **先确认 UI 是否被复位**（走第 3 条），
   并记住：**侧栏底部本来就没有常驻卡片**（走第 3b 条），应走账户菜单
6. 若锚点齐全但点击无效 → 走第 2 条（更新条噪声）或第 1 条（陈旧帧）
7. 若面板开着但点不中按钮 / T2 数字对不上 → 走第 4b 条（对话区同名文字）
8. 若账户行识别不到 → 走第 9 条（几何定位是否失效）
